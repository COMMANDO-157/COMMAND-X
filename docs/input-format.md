# CloudSentry Stage 3 input contract

Upload UTF-8 CSV with exact, unique header names, a JSON array, or `{ "observations": [...], "demo": true }`. Maximum 2 MiB and 5000 observations. CSV supports quoted fields, escaped quotes and quoted newlines. JSON objects and row fields reject unknown keys. Empty files, duplicate/overlapping intervals, malformed data and conflicting types for a resource are rejected before persistence. JSON numeric money is accepted only if its string representation is a valid decimal; prefer strings for exact financial input.

Required fields: `provider` (`aws`, `azure`, `gcp`), `account_id`, `region`, `resource_id`, `resource_type` (`compute`, `block_storage`), `timestamp` (ISO 8601 including UTC/offset), `interval_hours` (positive, at most 168, must represent a whole number of seconds), `currency` (three uppercase letters).

Optional fields: `cpu_percent`, `memory_percent` (0–100), `state` (`running`, `stopped`, `unattached`, `attached`), `attachment_count` (nonnegative integer), `hourly_rate`, `interval_cost`, `metadata`. Empty optional CSV fields or omitted fields become null, never zero. Prices must be nonnegative decimal values with at most 12 integral digits and eight fractional digits. Missing pricing produces a null projection, never an invented zero estimate.

`timestamp` starts the observed interval. IDs are trimmed for database identity while exact original input survives in raw evidence. Case is preserved; account and region are part of identity, as is provider. Different currencies are independently classified and summarized. Currency changes cannot supply each other's observation coverage. Imports hash the normalized sorted observations, so equivalent CSV/JSON imports deduplicate. Demo is a label supplied by the uploader, not proof of authenticity.

`metadata` is an optional strictly validated object (JSON text in a CSV cell). Supported keys: `demo` (boolean), `pricing_source` (string), `eligible_replacement_rate` (decimal), `replacement_pricing_source` (string), `storage_gib` (positive number), `monthly_rate_per_gib` (decimal). Supplied prices without a source are explicitly labeled `uploaded log (unverified)`. Replacement eligibility is uploader evidence, not a guaranteed available offer. Optional remediation fields are `terraform_address`, `resource_name`, `zone`, `project_id`, `subscription_id` and `original_configuration`. Configuration must be JSON-safe, at most 16 KiB, depth at most 8; prototype-related keys are rejected. This metadata never executes commands.

Detection uses duration-weighted nearest-rank p95 across observations and requires fully supplied dependent metrics. Waste rules require a span of at least 24 hours, at least 90% interval-union coverage, and at least two observations. All observations in the window must have the required explicit state. Idle (<5% CPU, <10% memory) takes precedence over over-provisioned (<20%, <40%), preventing overlapping waste estimates for the same resource.

Spike detection uses actual `interval_cost` on the latest one-hour interval and at least six contiguous preceding one-hour observations of the same currency. Median is the baseline. The latest cost must be strictly greater than 3× baseline and at least USD 1/hour above it. Zero baselines are supported without division. Other currencies do not use USD thresholds; no unsupported exchange rate is invented. Spike potential excess is shown separately from confirmed avoidable waste.

Prices use integer arithmetic at eight decimal places. Actual observed interval cost divided by interval hours is preferred for waste; otherwise hourly rate is used. Storage can use documented monthly GiB price × GiB / 720. Derived projection division truncates below the eighth decimal place, never using floating-point currency arithmetic. Spike comparisons preserve exact half-unit even medians through doubled integer arithmetic; evidence shows nine decimal places when needed. Spike projection rounds only after multiplying the exact excess by 720. Projection arithmetic rounds only the final projection: monthly GiB pricing therefore preserves the exact monthly amount rather than multiplying a prematurely truncated hourly rate. All projections use 720 hours and are estimates, not guaranteed savings.

Fixtures under `/fixtures/` are synthetic. Both `demo-cloud-spike.csv` and `.json` contain six USD 0.20 baseline hours and a USD 2.00 hour for exact AWS ID `i-0123456789abcdef0`. The focused engine test expects USD 1296 potential excess. Other JSON fixtures exercise idle compute, unattached storage, over-provisioning, insufficient evidence, and malformed rejection. No uploaded record executes cloud commands.
